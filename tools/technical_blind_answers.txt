T8-Q04: C is right on the missing justification (ISO 27001 6.1.3 d), but an examinee could argue the deeper problem is that the control is plainly applicable to a software developer, so even a written justification would not hold; the option only covers the missing reason.
T8-Q12: D assumes UU PDP requires the controller to tell the data subject about the erasure; I believe it does (Arts 43-44), but the "inform the customer" part is a detail an examinee might question. C (partial erasure) is clearly wrong.
T7-Q13: B paraphrases UU PDP Art 56 (equal or higher protection, or adequate binding safeguards), but it leaves out the third route, the data subject's consent. It is still the only defensible option.
T7-Q02: D (3 x 24 hours) matches UU PDP Art 46. Examinees used to GDPR's 72 hours will see the same figure, but notice to data subjects is also required under UU PDP, which is not true in all regimes. No real competing option.
T4-Q09: B is the standard compensating control; C (email the CIO after each release) is a weak detective control and gives no independent comparison with approved tickets, so B wins, though C is not unrelated.
T5-Q05: C (nonconformity) is right; a reader might argue about major vs minor, but the options do not make that distinction.
T6-Q14: C paraphrases the PCAOB definition ("reasonable possibility that a material misstatement ... will not be prevented or detected on a timely basis"); "go undetected" leaves out prevention, but it is still the only correct option.
